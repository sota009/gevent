# Codex Skill Format and gstack Generation Reference

Last checked: 2026-07-05

## External Codex Skill Format

Current OpenAI Codex docs define a skill as a directory with a required `SKILL.md` file and optional `scripts/`, `references/`, `assets/`, and `agents/openai.yaml`.

`SKILL.md` must include YAML frontmatter with:

- `name`
- `description`

Codex uses the `name`, `description`, and file path for initial discovery, then loads the full `SKILL.md` only when the skill is selected. Keep descriptions concise, scoped, and trigger-oriented.

Sources:

- https://developers.openai.com/codex/skills
- https://developers.openai.com/codex/concepts/customization

## gstack Source Of Truth

In this repository, do not hand-author generated Codex `SKILL.md` files.

The editable source is the `.tmpl` file:

- `<skill>/SKILL.md.tmpl`
- optional `<skill>/sections/*.md.tmpl`

Generate outputs with:

```bash
bun run gen:skill-docs
bun run gen:skill-docs --host codex
```

The generator and host config are the implementation source of truth:

- `scripts/gen-skill-docs.ts`
- `scripts/discover-skills.ts`
- `scripts/host-config.ts`
- `hosts/codex.ts`
- `test/gen-skill-docs.test.ts`

## Codex Host Behavior In gstack

`hosts/codex.ts` configures Codex generation as follows:

- Generated host subdir: `.agents`
- Local skill root: `.agents/skills/gstack`
- Global root currently configured as `.codex/skills/gstack`
- Frontmatter allowlist: `name`, `description`
- Description limit: 1024 characters, build error on overflow
- Metadata: generates `agents/openai.yaml`
- Skips the `codex` skill because that skill wraps Codex for Claude
- Rewrites Claude paths such as `.claude/skills` to `.agents/skills`
- Suppresses resolvers that would make Codex invoke itself

`.agents/` is gitignored and regenerated by setup. Do not commit generated `.agents/skills/gstack-*` output.

## Known Docs Delta

Current OpenAI Codex docs document user skills under `$HOME/.agents/skills`. This repository still has README/setup paths for `~/.codex/skills/gstack-*`.

Treat the repo implementation as authoritative for the current codebase, but do not propagate the older path into new explanatory docs unless intentionally documenting current setup behavior.

## Implementation Rule For Adding A gstack/Codex Skill

When importing a skill from another Codex thread:

1. Create or update the canonical `<skill>/SKILL.md.tmpl`.
2. Preserve gstack frontmatter conventions used by nearby skills.
3. Keep the description concise enough for Codex generation.
4. Use placeholders/resolvers only when they already exist or are added with tests.
5. Generate with `bun run gen:skill-docs` and `bun run gen:skill-docs --host codex`.
6. Commit source templates and generated tracked Claude `SKILL.md` files only.
7. Do not commit `.agents/`.
8. Verify with `bun test test/gen-skill-docs.test.ts`.
